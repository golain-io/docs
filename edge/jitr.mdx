title: JITR enrollment
description: Just-in-Time Registration — issue a fleet bootstrap certificate in the console, enroll Omega, and connect with mTLS.
---

**Just-in-Time Registration (JITR)** lets a device create itself on Golain the first time it boots. You issue one shared **fleet bootstrap certificate** in the console, flash the certificate into your image, and on first start Omega generates its own private key, asks the platform to sign it, and receives a **device certificate** plus the **MQTT broker URL**. No per-device secrets in your firmware, no manual console step per unit.

<Note>
  Omega generates the private key **on the device** and sends only a CSR. The private key never leaves the device and is never known to the platform.
</Note>

## When to use JITR

| Scenario | Approach |
|----------|----------|
| Factory or bulk provisioning — one image, many devices | **JITR** |
| A single device you already created in the console | [Connect](/edge/connect) with the MQTT credentials shown there |
| Dev laptop against a local stack | JITR against your local API, or auth bypass |

## How it works

1. In the console you issue a **fleet bootstrap certificate** and download the bundle.
2. On first boot Omega generates an ECDSA P-256 key pair and a CSR with `CN = device_name`.
3. Omega posts the CSR and the bootstrap certificate PEM to the platform JITR endpoint.
4. The platform verifies the bootstrap certificate, **creates the device record**, signs the CSR, and decrements the certificate's device quota.
5. Omega writes `device.crt`, `device.key`, and `metadata.json`, then connects over mTLS.

<Warning>
  **Do not pre-create the device in the console.** JITR creates the device record itself. If a device with the same name already exists in the project, enrollment fails with **409 `DEVICE_NAME_ALREADY_IN_USE`**.
</Warning>

## Before you start

| Requirement | How to get it |
|-------------|---------------|
| Organization, Project, and Fleet | [Console → Fleets and devices](/console/fleets-and-devices) |
| Permission to manage devices | Needed to click **Issue certificate** |
| Project device capacity | Enrollment fails if the project tier device limit is reached |

There is no per-fleet "enable JITR" toggle. A fleet supports JITR as soon as it has an active bootstrap certificate.

## Step-by-step

<Steps>

<Step title="Open Fleet & Devices">

In the console, open **Fleet & Devices** for your project. Pick the fleet that will own the devices (or create one first).

<img src="/images/edge/jitr/01-fleet-list.jpg" alt="Fleet & Devices list showing fleets such as Production Sensors" />

</Step>

<Step title="Open the fleet">

Click the fleet name. You land on the **Devices** tab — leave it empty for JITR fleets. Devices appear here after enrollment.

<img src="/images/edge/jitr/02-fleet-devices.jpg" alt="Fleet detail page open on the Devices tab" />

</Step>

<Step title="Open Certificates">

Select the **Certificates** tab. Active bootstrap certificates show serial, status, devices enrolled (used / quota), and expiry.

<img src="/images/edge/jitr/03-certificates-tab.jpg" alt="Certificates tab listing bootstrap certificates with Issue certificate button" />

</Step>

<Step title="Issue a bootstrap certificate">

Click **Issue certificate**. Set **Device quota** (1–1000) — how many devices this certificate may enroll. Quota is fixed once issued. Certificates are valid for **90 days**.

<img src="/images/edge/jitr/04-issue-modal.jpg" alt="Issue bootstrap certificate modal with device quota field" />

Click **Issue certificate** to create it.

</Step>

<Step title="Download the bootstrap bundle">

The console shows serial, certificate ID, quota, and expiry. **Download immediately.**

<img src="/images/edge/jitr/05-issued-download.jpg" alt="Bootstrap certificate issued modal with Download bootstrap bundle button" />

<Warning>
  The private key is returned **exactly once** and is never stored by the platform. If you close without downloading, revoke the certificate and issue a new one.
</Warning>

The zip contains:

| File | Use |
|------|-----|
| `bootstrap-certificate.pem` | Flash onto every device (`bootstrap_cert_path`) |
| `bootstrap-private.key.pem` | Keep in your provisioning system — Omega does not need it on device |
| `bootstrap-ca.pem` | CA chain for verification |
| `jitr-config.yaml` | Ready-to-merge `connection.jitr` block with org, project, and fleet IDs filled in |

After download, the modal confirms the bundle was saved. Click **Done**.

<img src="/images/edge/jitr/06-downloaded.jpg" alt="Issued modal after bundle download confirmation" />

</Step>

<Step title="Confirm the certificate is active">

The Certificates table lists the new certificate as **active**. Use **Revoke** if a bootstrap certificate or its key ever leaks — already-enrolled devices keep working.

<img src="/images/edge/jitr/07-certificates-list.jpg" alt="Certificates table with active bootstrap certificate and Revoke action" />

</Step>

<Step title="Place the bootstrap certificate on the device">

Copy `bootstrap-certificate.pem` into your image, for example `/etc/omega/bootstrap.crt`. The same file goes on every device in the fleet.

```bash
install -m 0600 bootstrap-certificate.pem /etc/omega/bootstrap.crt
```

<Note>
  Omega reads only the bootstrap **certificate** for the JITR call. Keep `bootstrap-private.key.pem` offline in your factory or CI secrets store.
</Note>

</Step>

<Step title="Add the JITR block to your Omega profile">

Merge the `connection.jitr` block from `jitr-config.yaml` into your client profile (or paste the values by hand):

```yaml
connection:
  transport: mqtt
  # server_url is overwritten by the broker URL the platform returns
  root_topic: "/{org4}_{project4}/{device-name}"   # see next step

  jitr:
    api_base_url: "https://api.ilyama.golain.io/core/api/v1"
    bootstrap_cert_path: "/etc/omega/bootstrap.crt"
    cert_dir: "/var/lib/omega/certs"
    org_id: "<org-uuid>"
    project_id: "<project-uuid>"
    fleet_id: "<fleet-uuid>"
    device_name_env: OMEGA_DEVICE_NAME
```

| Field | Required | Description |
|-------|----------|-------------|
| `api_base_url` | Yes | Platform API v1 root (includes `/core/api/v1`). Trailing `/` is trimmed |
| `bootstrap_cert_path` | Yes | Path to the fleet bootstrap certificate PEM |
| `org_id` | Yes | Must match the bootstrap certificate's org |
| `fleet_id` | Yes | Must match the bootstrap certificate's fleet |
| `project_id` | Yes | Project the device is created in |
| `device_name` / `device_name_env` | Yes | Becomes the certificate `CN` and the device name. **Must be unique in the project** |
| `cert_dir` | No | Where issued material is written. Defaults to `var/config/certs` |

Omitting the `jitr:` block entirely disables JITR.

**Per-device values via environment variables.** `device_name` differs on every unit, so set it from the environment rather than baking it into the image:

```yaml
  jitr:
    api_base_url_env: OMEGA_API_BASE_URL
    bootstrap_cert_path_env: OMEGA_BOOTSTRAP_CERT_PATH
    org_id_env: OMEGA_ORG_ID
    project_id_env: OMEGA_PROJECT_ID
    fleet_id_env: OMEGA_FLEET_ID
    device_name_env: OMEGA_DEVICE_NAME
```

The environment value wins when the named variable is set and non-empty; otherwise the YAML value stands. Load a file of these with `omega-agent --env /etc/omega/device.env`.

</Step>

<Step title="Set the root topic">

This is the most common cause of a "successful" enrollment that then goes silent.

After enrollment Omega defaults `root_topic` to `omega/{device_id}` if you left it empty — and that topic is **denied by the broker ACL**. mTLS connects fine, then every subscribe fails and the broker disconnects on the first publish.

The broker authorizes devices under:

```
/{org-uuid-last4}_{project-uuid-last4}/{device-name}/...
```

For org `…e023` and project `…4f19` with device `press-01`, that is `/e023_4f19/press-01`. The leading slash is required.

<Tip>
  After the device enrolls, open it in the console and copy the assigned root topic from the device page rather than assembling it by hand. Set it with `root_topic` (or `OMEGA_ROOT_TOPIC` via `root_topic_env`).
</Tip>

</Step>

<Step title="Run Omega">

```bash
cargo build --release -p omega-agent
./target/release/omega-agent --client /etc/omega/profile.yaml --env /etc/omega/device.env
```

On first start Omega enrolls, then connects. It writes three files into `cert_dir`:

| File | Contents |
|------|----------|
| `device.crt` | Issued certificate chain |
| `device.key` | Device private key, generated locally |
| `metadata.json` | `device_id` and `mqtt_broker_url` |

On later starts Omega **skips enrollment** if `device.crt` and `device.key` exist, are non-empty, and the certificate is valid with **more than 24 hours** remaining. Otherwise it enrolls again.

<Warning>
  `omega-agent --validate` does **not** exercise the JITR block or attempt enrollment — it only checks profile structure. A broken `jitr:` block surfaces on the first real run.
</Warning>

</Step>

<Step title="Verify in the console">

Omega logs the assigned device id and broker URL. In **Fleet & Devices**, open the fleet — the new device appears under **Devices**. Open it to confirm identity, MQTT details, and connectivity.

<img src="/images/edge/jitr/08-device-detail.jpg" alt="Device detail page after JITR enrollment" />

On the **Certificates** tab, the bootstrap certificate's **Devices enrolled** count increments by one per successful enrollment.

</Step>

</Steps>

## Enroll without starting the agent

`omega-core` ships a one-shot binary for factory tooling and CI. It performs the same enrollment and writes the same three files, then exits.

```bash
cargo build --release -p omega-core --bin omega-jitr-enroll

export OMEGA_E2E_API_BASE_URL=https://api.ilyama.golain.io/core/api/v1
export OMEGA_BOOTSTRAP_CERT_PATH=/etc/omega/bootstrap.crt
export OMEGA_E2E_ORG_ID=<org-uuid>
export OMEGA_E2E_PROJECT_ID=<project-uuid>
export OMEGA_E2E_FLEET_ID=<fleet-uuid>
export OMEGA_JITR_DEVICE_NAME=press-01
export OMEGA_JITR_CERT_DIR=/var/lib/omega/certs   # optional, defaults to .

./target/release/omega-jitr-enroll
```

Output on success — exit code `0`:

```
device_id=…
broker_url=mqtts://mqtt.ilyama.golain.io:8883
cert_dir=/var/lib/omega/certs
```

Any failure prints `Error: …` to stderr and exits `1`. This binary takes no flags; every value comes from the environment, and all except `OMEGA_JITR_CERT_DIR` are required.

## Certificate lifetime and renewal

Device certificates are valid for **90 days**. Renewal runs over MQTT once the device is connected, configured under `connection.cert_renewal`:

```yaml
connection:
  cert_renewal:
    enabled: true
    renew_window_days: 14
```

Set `OMEGA_CERT_RENEW_FORCE=1` to force a renewal attempt regardless of the window when testing.

If a device is offline long enough for its certificate to lapse, the 24-hour re-enrollment rule takes over: on next boot Omega runs JITR again, which **creates a new device record** unless the name is reused within the idempotency window. Plan connectivity so devices renew before expiry.

## Managing bootstrap certificates

| Action | Where |
|--------|-------|
| Issue | Fleet → **Certificates** → **Issue certificate** |
| List | Fleet → **Certificates** |
| Revoke | Fleet → **Certificates** → **Revoke** |

Revoke immediately if a bootstrap certificate or its key leaks — it can enroll any device into that fleet up to its remaining quota. Revoking does not affect devices already enrolled with it.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `400 invalid bootstrap_cert_pem` | File is not a PEM certificate, or is the key rather than the cert | Point `bootstrap_cert_path` at `bootstrap-certificate.pem` |
| `400 bootstrap cert not signed by this CA` | Certificate came from a different stack | Reissue against the stack in `api_base_url` |
| `400 bootstrap cert is outside its validity window` | Past 90 days, or device clock is wrong | Reissue, or fix device time (NTP) |
| `400 bootstrap cert not found` | Serial not in the registry | Reissue |
| `400 bootstrap cert is not active` | Revoked | Issue a new one |
| `400 bootstrap cert fleet mismatch` / `org mismatch` | `fleet_id` or `org_id` doesn't match the certificate | Correct the JITR block |
| `403 BOOTSTRAP_QUOTA_EXHAUSTED` | `max_devices` reached | Issue another certificate |
| `409 DEVICE_NAME_ALREADY_IN_USE` | Name taken — often from pre-creating the device | Use a unique `device_name`; don't pre-create |
| `409 in progress` | Concurrent request with the same idempotency key | Retry shortly |
| `400 PROJECT_DEVICE_LIMIT_REACHED` | Project tier device cap | Raise the tier or remove devices |
| `connection.jitr.<field> is required` | Empty field, or the `*_env` variable is unset | Set the value or export the variable |
| Enrolls, connects, then goes silent | `root_topic` doesn't match the broker ACL | Set `root_topic` to `/{org4}_{project4}/{device-name}` |
| Enrollment failure stops the agent | There is no retry or backoff — one attempt, then exit | Supervise with systemd `Restart=on-failure` |

<Note>
  Enrollment failures are fatal to startup by design: a single request, no retry loop. Run Omega under a supervisor so transient API outages are retried by process restart.
</Note>
